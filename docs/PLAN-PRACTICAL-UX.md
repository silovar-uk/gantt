# Gantt Desk 実用化計画 ― 思想・作戦・仕様

作成日: 2026-09-18 / 対象: `silovar-uk/gantt`(https://silovar-uk.github.io/gantt/)
調査時点の `origin/main`: `5711248`

---

## 結論

このアプリが実用的でない理由は、ボタンが足りないからではありません。**画面が、入れたデータの実物を映していない**ことです。40件の予定を取り込んでも、チャートに描かれるのは6本です。残り34件は横スクロールもできず、画面上に存在しません。「全体」を押すと、今度はバーが1本もない抽象表示に落ちます。

したがって本計画は、配色や部品の磨き込みではなく、**画面が嘘をつかない状態を作ること**から始めます。そのうえで、パン・ズーム・全体表示を一つの部品(時間の窓)へ統合し、守破離をUIの構造として通します。

範囲は次の5段階です。停止点は第2段の見た目確認の1回だけです。

| 段 | 内容 | 得られるもの |
|---|---|---|
| 0 | 嘘をなくす | 入れた予定が全部見える。押して何も起きないボタンが消える |
| 1 | 届かない機能を届かせる | スマホでガントが見える。マウスで削除できる |
| 2 | 時間の窓 | パン・ズーム・全体・現在地が一つの部品になる(**ここで1回停止**) |
| 3 | 守破離を通す | 自動と手動の関係が画面に出る。いつでも自動へ戻せる |
| 4 | 静かになる案内・整合 | 使うほどヒントが引っ込む。READMEと死蔵ファイルを整理 |

## 思想

### 芯

> **見えているものが、すべてである。**

画面の外にデータを隠さない。同時に、画面に出ているものは必ず本物である。この一文がすべての判断基準です。

いまのアプリは、この一文を両側から破っています。40件入れて6本しか見えないのは前半の違反です。押しても何も起きないボタンが本物の顔をしているのは後半の違反です。

### 三つの原則

**1. 不在を作らない**

表示期間の外に予定があるなら、黙って消しません。取り込み・追加・日付変更のたびに、全件が視野に入る状態を既定にします。それでも外に出るもの(絞り込みなど)は、件数と戻り道を必ず画面に出します。

**2. 一つの操作に、一つの意味**

押しても何も起きないボタンを置きません。DOMにあるのに見えないコントロールを残しません。ラベルと挙動を一致させます。「置換」が置換しないなら、ラベルを直します。

**3. 密度は機械が、意味は人が決める**

行の高さ・日付幅・表現(行かShapeか)は、件数と画面の高さから機械が決めます。人が決めるのは「何を見たいか」(絞り込み・並び・選択)だけです。人が密度に手を出したときは、そのことを画面に残し、いつでも機械に戻せるようにします。

### 何を足さないか

- ダークモード、Webフォント、依存パッケージは足しません。
- 新しい概念(Macro、Surface、Rhythm のような内部語)をユーザーに学ばせません。
- レイヤーを積み増しません。不具合は原因のファイルを直接直します。純増するファイルは1本だけです。

## 守破離の設計

### 誤った適用を避ける

守破離を「初心者モード / 中級者モード / 上級者モード」の切替として実装してはいけません。モードの存在自体が学習コストになり、どのモードにいるかを常に気にさせます。UXが下がります。

正しい適用は、**画面は一つのまま、同じ部品が使う人の熟達に応じて意味を増やすこと**です。

| 段階 | 意味 | 設計への要求 |
|---|---|---|
| 守 | 何も知らなくても、迷わず正解に着く | 既定値が正しい。手を出さなくても完成している |
| 破 | 既定を外したくなったとき、その場で外せる | 外したことが画面に残り、いつでも守へ戻れる |
| 離 | 毎回同じことをする人が、手順を飛ばせる | キーボード・ドラッグ・直接操作。知らなくても損をしない |

### 主要3部品への適用

| 部品 | 守 | 破 | 離 |
|---|---|---|---|
| **時間の窓** | 起動時・取り込み直後は全期間に合う。窓は全体を指す。何もしなくてよい | 窓をドラッグして期間を動かす。端を掴んで伸縮。外れると「全体」チップが出る | 窓上でホイール=ズーム、ダブルクリック=その月、`F`=全体、`T`=今日 |
| **行とバー** | 行の高さ・文字サイズ・表現を件数と高さから自動決定。選ばなくてよい | つまみで行を上下すると自動が外れ、「自動」チップが出る | バーをドラッグで移動、右端で期間変更、行で `Enter`=詳細 `Delete`=削除 `↑↓`=移動 |
| **予定の編集** | 行の名前欄に直接打てば保存される。モーダルを開かなくてよい | 「•••」で詳細モーダル。カテゴリ・色・メモ・締切まで | 複数選択して一括で日付をずらす、`Ctrl+Z` で戻す |

### 「破」を必ず見えるようにする

守破離が機能する条件は、**いま自分が破にいると分かること**です。分からなければ、人は自分が壊したのか仕様なのか判別できません。

そこで、既定から外れた状態はすべて同じ形のチップで表します(`.revert-chip`)。押せば守に戻ります。

- 期間を手で動かした → 窓の横に「全体」
- 行の高さを手で変えた → つまみの横に「自動」
- 絞り込みを掛けた → 条件バーのチップ(既存の仕組みを流用)

### 驚き ― 使うほど、画面が静かになる

守破離をUIが体現する仕掛けを1つ入れます。

**覚えた操作の案内は、引っ込みます。**

- 初めてバーに触れた人には「ドラッグで日付を動かせます」が淡く出ます。
- 3回ドラッグしたら、二度と出ません。
- 詳細モーダルも、期間の操作も同じです。

派手な演出ではありません。使い込むほど画面から言葉が減っていき、最後には図だけが残ります。離に到達したことが、静けさとして返ってきます。押し付けにならないよう、「その他」メニューの最下段に「操作のヒントを出す」を置き、いつでも守に戻せるようにします。

実装コストは低く保ちます。localStorage にカウンタを1つ持ち、`count < 3` で出し分けるだけです。

## 仕様

### S1. 取り込み・サンプル追加のあとに全件が見える

**最優先の修正です。**

`08.js` の `applyImport()` と `09.js` の `loadSample()` の完了時に、取り込んだ予定のいずれかが現在の表示期間の外にあるなら `fitOverview({ reason: 'explicit' })` を呼びます。

- 判定: `tasks.some(t => t.start < view.end === false || t.end > view.end || t.start < view.start)` を素直に書きます。
- `fitOverview` は `13-overview-density.js:156` にあります。`fitAll()`(`08.js:167`)ではなく、表現の解決まで行うこちらを使います。
- 新規タスク作成(`save-task` の新規経路)でも、作った予定が期間外なら期間を広げます。全体には合わせません。追加のたびに視点が飛ぶのを避けるためです。

### S2. 期間外の予定を、必ず知らせる

絞り込みや手動操作で期間外に予定が残る場合、条件バー(`#condition-bar`、描画は `06.js`)に次を出します。

```
この期間の外に 12件  [全体を表示]
```

- 件数は `filteredTasks()` のうち `task.end < view.start || task.start > view.end` の数です。
- 「全体を表示」は `fitOverview({ reason: 'explicit' })` を呼びます。
- 0件のときは行ごと出しません。`[hidden]` ではなく、描画しない形にします。

### S3. 「全体」でバーが消える問題

`13-overview-density.js:5` の `ROW_MIN` を `20` → `14` にします。

- 40件 × 14px = 560px となり、1440×900 では行表示に収まります。
- 14pxの行では文字を出さず、色帯とカテゴリ点だけにします(`v7` 側で `--row-h < 18px` のときのルールを1つ追加)。
- Shapeへ落ちるのは、14pxでも収まらないとき(1440×900でおよそ50件超)に限ります。Shape自体は廃止しません。
- `REPRESENTATION_HYSTERESIS`(`:13`)は `ROW_MIN * 2` の式のままにします。値は自動で28になります。

あわせて、Shape表示のヘッダー(「全体 N件 · M分類」)の右に `1件ずつ見る` を1つ置きます。押すと行表示へ降ります(`overviewMacroMode = false`)。現状はレンズ(`v10`)が唯一の降り口で、到達が分かりにくいためです。

### S4. 押しても何も起きないボタンをなくす

`10.js:132` の `save-status` 分岐から条件を外し、常に `openModal('export')` を開きます。

```js
else if (action === 'save-status') openModal('export');
```

「このブラウザに保存済み」の自然な続きは「書き出し・復元」です。押した人の期待から外れません。

### S5. カテゴリ色の衝突をなくす

`02.js:166` と `01.js:174` の色割り当てを、**既存カテゴリで未使用の色を優先**する形に変えます。

```js
const used = new Set(tempCategories.map((c) => c.color));
const color = COLOR_PALETTE.find((c) => !used.has(c))
  || COLOR_PALETTE[tempCategories.length % COLOR_PALETTE.length];
```

- 9分類目以降は必ず衝突します。プロジェクト設定のカテゴリ節に「9分類以上では色が重なります」と小さく添えます。
- `COLOR_PALETTE` の8色名と順序は変えません。保存データとJSONの互換のためです。

### S6. モバイルでガントを見られるようにする

`v6-workspace-ux.css:14-18` の `display: none !important` ブロックを整理します。

- `#mode-switch` を**モバイル幅でだけ**表示します。ただし3択ではなく `一覧 / ガント` の2択にします。`分割` はモバイルでは元々無効です(`05.js:281`)。
  - 置き場所はツールバー右端、`その他` の左です。
  - デスクトップでは引き続き非表示にします。分割で足りており、ツールバーを太らせないためです。
- `#scale-switch`(日/週/月)は**削除**します。markup(`05.js:228-230`)とhandler(`10.js:15-16`)を消します。時間の窓ができれば冗長です。
  - `viewSettings.scale` はストレージに残すため、スキーマは変えません。既定の `'day'` のままです。
- `[data-action="today"]` と `[data-action="display-settings"]` は「その他」メニューにあります。ツールバーには出しません。

### S7. マウスで削除できるようにする

詳細モーダルのフッター(`06.js:258` 付近)の左端に「削除」を追加します。

```html
<button class="link-button danger" type="button" data-action="delete-task" data-task-id="${task.id}">削除</button>
```

`10.js` に分岐を追加します。`confirm()` は使いません。

- 削除を実行し、トーストに「「予定名」を削除しました」と「元に戻す」を出します。
- 「元に戻す」は既存の `undo()` を呼びます。`contentCommit` が履歴に積むため、追加の仕組みは不要です。
- 新規作成中(`e.isNew`)は削除を出しません。

### S8. `confirm()` をなくす

| 箇所 | 変更後 |
|---|---|
| 予定の削除(`10.js:212`) | 実行してトーストでUndo(S7と同じ) |
| カテゴリの削除(`09.js:114`) | 同上。「N件は未分類へ移動しました」をトーストに含める |
| 保留項目の削除(`10.js:104`) | 同上 |
| サンプル追加(`09.js:124`) | 確認を廃止。追加してトーストでUndo |
| 下書きの破棄(`10.js` の `new-input-draft`) | モーダル内のインライン確認(「破棄する / やめる」) |
| 保存済みへ切り替え(`10.js` の `reload-saved`) | 同上。失うものを文で示す |

### S9. 「予定を置換」のラベルを実態に合わせる

`08.js` の `importModeOptions()` のラベルを変えます。挙動は変えません。

| 現在 | 変更後 |
|---|---|
| 予定を追加 | 予定を追加 |
| 予定を置換 | **予定をすべて入れ替え** |
| プロジェクトを復元 | プロジェクトを復元(backup形式のみ) |

検証OKのプレビューに1行加えます。

```

```

全部を入れ替えたい人の受け皿は、backup形式の「プロジェクトを復元」です。既に存在します。

### S10. 時間の窓(Time Window)

`src/v5/classic/18-time-compass.js` と `assets/v12-time-compass.css` を作り替えます。**新規ファイルは作りません。**

#### 構造

ヘッダー下、現在のCompassと同じ位置に置きます。高さはデスクトップ44px、モバイル36pxです。

```
[━━━━━━━━━━密度━━━━━━━━◆━━━━━━━━━━━━━◆━━━━]   ← 地: プロジェクト全期間
            ┃         │                        ┃
            [ ░░░░░░ 窓 ░░░░░░ ]                     ← 窓: いま見ている期間
                                    ▲today
                                                (全体)  ← 破のときだけ出るチップ
```

| 層 | 内容 | 流用元 |
|---|---|---|
| 地 | 全期間(`min(task.start)` 〜 `max(task.end)`、両端に3%の余白) | 新規計算 |
| 密度 | 期間ごとのタスク密度を薄い帯で表示 | 既存の `BUSY_BUCKETS` ロジック |
| 標 | マイルストーンと締切のピン | 既存の `.time-compass-milestone` |
| 今日 | 縦線 | 既存 |
| 窓 | `viewSettings.start` 〜 `end` を明るい矩形で重ねる。左右に掴み手 | 新規 |

#### 操作

| 操作 | 結果 | 段階 |
|---|---|---|
| 何もしない | 窓は全期間を指す(起動・取り込み直後) | 守 |
| 窓の中をドラッグ | 期間が平行移動(パン) | 破 |
| 窓の端をドラッグ | 期間が伸縮(ズーム) | 破 |
| 地をクリック | その日を中心に、いまの幅で移動 | 破 |
| 窓上でホイール | カーソル位置を軸にズーム | 離 |
| ダブルクリック | その月に合わせる | 離 |
| `F` | 全体へ | 離 |
| `T` | 今日を中心へ | 離 |

- 窓が全期間と一致しないとき、右端に「全体」チップを出します(S11)。
- ポインタ操作は Pointer Events を使い、マウスと指を同じコードで扱います。
- ドラッグ中は `requestAnimationFrame` で1フレーム1回だけ再描画します。既存の `compassFrame` の仕組みを流用します。
- 期間の下限は7日、上限は730日です。既存の上限に合わせます。
- 既存の `拡大 / 縮小`(`v11` の `.ux-zoom`)と `全体` ボタンは残します。守の人にはボタンが要ります。
- `前の期間` / `次の期間`(`06.js:19`)は削除します。窓で代替されます。
