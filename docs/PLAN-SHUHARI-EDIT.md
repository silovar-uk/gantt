# Gantt Desk 守破離計画 ― どこを触っても、同じ予定

作成日: 2026-09-19 / 対象: `silovar-uk/gantt`(https://silovar-uk.github.io/gantt/)
調査時点の `origin/main`: `044cd1e` / 実装担当: Sonnet

---

## 結論

このアプリには、同じ予定の顔が2つあります。左の一覧の行と、右のガントのバーです。
しかし**力が同じではありません**。左の行は名前も日付も直せて、`•••` から全項目に届きます。
右のバーはクリックしても選択されるだけで、編集への入口が画面上にありません。

つまり、いまの状態は「左は本物、右は絵」です。本計画はこれを解消します。

芯は一文です。

> **どこを触っても、同じ予定。**

そのうえで守破離を、前回とは別の軸で通します。前回の守破離は「アプリが人の熟達に合わせる」(既定→逸脱→近道)で、`044cd1e` で実装済みです。
今回は「**一つの予定への、関与の深さ**」です。確かめる→その場で直す→触らずに動かす。そして、どの段にも左右どちらからでも入れます。

範囲は4段です。停止点は第1段の見た目確認の1回だけです。

| 段 | 内容 | 得られるもの |
|---|---|---|
| 1 | 予定カード(左右共通)とバーの `•••` | バーをタップすれば直せる。左右の力が揃う(**ここで1回停止**) |
| 2 | 指とキーボードを右側へ通す | スマホのガントで編集できる。キーボードでバーに届く |
| 3 | 置く前に結果が見える / 選んだものが必ず見える | ドラッグの往復が消える |
| 4 | 名前・複数選択・モバイルのツールバー | 画面外に隠れた操作が消える。一括変更ができる |

## 思想

### 芯

> **どこを触っても、同じ予定。**

表現が違うだけで、扱えることが減ってはいけません。左の行と右のバーは、同じ予定の二つの顔です。

### 三つの原則

**1. 表現が違っても、力は同じ**

一覧の行でできることは、バーでもできます。逆も同じです。片方にしか無い操作を作りません。
「一覧は編集用、ガントは閲覧用」という分業は、画面の狭いスマホで真っ先に壊れます。

**2. 選択は、道具になる**

選んだ結果が必ず何かに使えます。いまは選んでも帯が光るだけで、そこから先がありません。
選択は状態ではなく、次の一手への入口にします。1件なら予定カード、2件以上ならまとめて直すカードです。

**3. 結果は、確定する前に見える**

ドラッグ中に、動いた先の日付と、締切を越えるかどうかを出します。
置いてから確かめてUndoする往復を、置く前の1回に畳みます。

### 何を足さないか

- 依存パッケージ、ビルド、フレームワークを足しません。
- ダークモード、Webフォントを足しません。
- 新しいモード(初心者/上級者)を作りません。守破離をモード切替として実装しません。
- 先行・後続の依存関係やクリティカルパスは扱いません。別の製品の話です。
- 純増するファイルは `21-task-card.js` と `v14-task-card.css` の2本だけです。
- 部品は1つ減らします(`#ux-selection-badge` を予定カードへ吸収)。

## 守破離の設計

### 今回の軸

| 段 | ユーザーがしていること | 画面 |
|---|---|---|
| 守 | 確かめる | 触れば、触れたところに予定カードが出る。名前・期間・カテゴリー・メモが読める |
| 破 | その場で直す | 同じカードの中で直す。閉じれば保存済み。全項目はモーダルへ |
| 離 | 触らずに動かす | ドラッグ、キーボード、複数選択の一括 |

前回の守破離(既定→逸脱→近道)は残したうえで、この軸を重ねます。
守破離を層にするのではなく、**一つの部品が三段すべてを持つ**形にします。段を移るのに切替が要りません。

### 部品ごとの適用

| 部品 | 守 | 破 | 離 |
|---|---|---|---|
| **予定カード** | タップで出る。読むだけでよい | その場で名前・日付・カテゴリー・完了を直す | `‹ ›` で閉じずに次の予定へ。`Enter` で開き `Esc` で閉じる |
| **バー** | 色と位置を読む。`•••` が編集できると告げる | タップでカード。ドラッグで日付 | 端で伸縮、`Alt+←→`、Shift+クリックで複数選択 |
| **まとめてカード** | 2件以上選ぶと出る。何件かが分かる | カテゴリー・完了・日付をまとめて変える | Shift+クリックで選び足す。`Alt+←→` は開かずに効く |

## 驚き ― 置く前に、結果が見える

前回の驚きは「使うほど画面が静かになる」でした。今回は逆向きに、**手を動かしている最中だけ饒舌になる**ものを置きます。

バーを掴んでいる間、バーの上に小さなラベルが出ます。

```
7/16 → 7/19  (9日間)  +3日
```

そして、その予定が**同じカテゴリーの締切マイルストーンを越えるとき**だけ、ラベルが琥珀色になり一言足します。

```
7/16 → 7/26  (9日間)  +10日
締切「プラン確定」を2日超えます
```

同時に、時間の窓のその締切ピンが光ります。指を離す前に分かります。

これは演出ではなく短縮です。いまは、置く→トーストを読む→ずれていたらUndo、の3手が要ります(事実E)。
予告が出れば1手で置けます。驚きは「アプリが先に知っていた」という感覚から来ます。
派手さは足しません。`prefers-reduced-motion` で挙動を変える必要もありません。アニメーションを使わないからです。

**小さいほうの驚き**: 予定を選ぶと、時間の窓の上でもその期間が光ります(`#project-ribbon-track`)。
「全体の中ではここ」が、視線を動かさずに分かります。10行程度で済みます。

## 仕様

### S1. 予定カード(Task Card)

**新規 `src/v5/classic/21-task-card.js`(200行程度)と `assets/v14-task-card.css`。**

#### 開く

| 操作 | 結果 |
|---|---|
| バー / マイルストーンをクリック・タップ | そのバーに沿って予定カード。選択も同時に行う |
| バーの `•••` をクリック・タップ | 同じカード(S2) |
| 一覧行の `•••` | 同じカード。行の右に出る |
| モバイルのガントの予定名をタップ | 同じカード(事実B の修正) |
| 行 / バーにフォーカスして `Enter` | 同じカード |
| 一覧行の本体をクリック | 選択のみ。カードは出さない(現状維持) |
| Shift+クリック | 複数選択。カードは出さない(S11 のまとめてカードへ) |
| ドラッグ(移動量6px以上) | カードは出さない |

`data-action="details"` の飛び先を、モーダルから予定カードへ変えます(`10.js:39`)。
これで左の `•••` と右のバーが**同じ部品**を開きます。「左側のメニュー同様」が、似せるのではなく同一になります。
従来の詳細モーダルは、カードの「すべての項目」から開きます。消しません。

#### 中身(デスクトップ、幅280px)

```
┌──────────────────────────────┐
│ ● 工程5 運営作業            × │  ← 名前は入力欄。その場で直せる
│ 2026/07/16 → 2026/07/24  9日間│  ← 日付2つ。その場で直せる
│ カテゴリー  運営          ▾   │
│ ☐ 完了                        │
│ メモ  会場の仮押さえ…          │  ← 1行。クリックで3行に開く
├──────────────────────────────┤
│ 削除   すべての項目   ‹ 5/40 › │
└──────────────────────────────┘
```

- 名前・日付・カテゴリー・完了・メモは、**変えた瞬間に保存**します。カードに「保存」ボタンを置きません。
  - 名前は `focusout` と `Enter`、日付とカテゴリーと完了は `change`、メモは `focusout`。既存の `updateInlineName`(`10.js:205`)と同じ作法です。
  - 保存経路は既存の `contentCommit` です。新しい保存経路を作りません。
- マイルストーンのときは日付欄を1つにします(`editorFormHTML` と同じ分岐)。
- 「すべての項目」= 既存 `openModal('details', { task })`。カードは閉じます。
- 「削除」= 既存 `deleteTask(id)`。トーストに「元に戻す」を出します(`showToast(msg, false, true)`)。カードは閉じます。
- `‹ 5/40 ›` = `filteredTasks()` の並びで前後の予定へ。**カードを閉じずに移動**し、アンカーもその予定へ移ります。
  - 40件を1件ずつ確認する作業が、カードを開き直さずに終わります。レビュー時に効きます。
  - `←` `→` キーでも同じ(カードが開いている間のみ)。

#### 開き方・閉じ方・位置

- 要素は `<div popover="auto">` を使います。`Esc` と外側クリックでの閉じ、最前面への配置がブラウザ側で得られます。自前で実装しません。
- 位置は `position: fixed` で、開いたときに1回だけ実測して決めます。
  - 既定はアンカーの直下。下に入らなければ上。左右は画面内にクランプ(端から8px)。
  - `#timeline-scroll` と `#task-scroll` のスクロール中は、`requestAnimationFrame` で1フレーム1回だけ位置を更新します。閉じません。
  - アンカーが再描画で消えたら(`isConnected === false`)、`data-timeline-task` / `data-task-row` から引き直します。引けなければ閉じます。
- 開いたまま別のバーをクリックしたら、そのバーへ移ります。閉じて開き直しません。
- 行の高さが14pxでも成立します。カードはバーの**外**に出るためです(事実M)。

#### モバイル

- 同じ要素のまま、CSSでボトムシートにします(`@media (max-width: 767px)`)。
  - 全幅、下端に吸着、`padding-bottom: env(safe-area-inset-bottom)`、角丸は上だけ。
  - JSの分岐は「アンカー計算を飛ばす」1箇所だけにします。
- 上端に掴み手(4px × 36pxの線)を描きます。押し下げで閉じる実装は**しません**。見た目だけで、閉じるのは `×` と背景タップです。
  - `ponytail:` 掴み手は飾り。スワイプで閉じたくなったら `pointermove` を20行足す。

#### アクセシビリティ

- カードは `role="dialog"` `aria-label="<予定名> の詳細"`。
- 開いたとき、名前の入力欄へフォーカスを移します。
- 閉じたとき、開く前のアンカーへフォーカスを戻します。
- バーの `aria-label` を「<予定名> 2026/07/16〜07/24 詳細を開く」に変えます(いまは日付のみ)。

### S2. バーに `•••` を出す

ユーザーの要求は「右側のアイコンをクリックしても編集できること」です。
**バー本体のタップでもカードが開くようにしたうえで、アイコンも出します。** 冗長ですが、その冗長さが手がかりになります。

- 位置はバーの**右端の外側**(`position: absolute; left: 100%; margin-left: 4px`)。`.task-bar.ux-draggable` は既に `overflow: visible` です。
- 大きさは行の高さに関係なく16px固定。当たり判定は `::before` で28×28まで広げます。
- 出る条件:
  - ポインタがある環境(`@media (hover: hover)`): バーのhover時、または選択中のバー。
  - タッチ環境(`@media (hover: none)`): **選択中のバーにだけ常時表示**。hoverが無いためです。
- マイルストーン(◆)にも同じものを出します。
- `aria-hidden="true"` にはしません。`aria-label="<予定名>の詳細"` を付けます。
- バーの右端が表示領域の右端に近いときは、`•••` を内側(`right: 4px`)へ寄せます。

### S3. 左右で同じ力になったことを検査する

第1段の完了条件を、目視ではなく検査で固定します。

新規 `scripts/public-e2e-task-card.mjs`:

1. デスクトップ1440×900。サンプルを入れ、分割表示で最初のバーをクリック → `.task-card` が表示される。
2. 同じ予定の一覧行の `•••` をクリック → `.task-card` が表示され、名前欄の値が一致する。
3. カードの名前を変更して外をクリック → 一覧行の `[data-inline-name]` と バーの `title` の両方に反映される。
4. `‹ ›` で次の予定へ移り、カードが開いたままで名前が変わる。
5. 375×812、ガント表示で予定名をタップ → `.task-card` が表示される(事実B の回帰検査)。
6. 375×812でカードが `.task-card.is-sheet` になり、幅が画面幅と一致する。

### S4. 指でガントを扱えるようにする

- `.task-bar.ux-draggable` と `.milestone.ux-draggable` の `touch-action: none` を `pan-y` に変えます(`v6-workspace-ux.css:60, 64`)。
  - バーの上からでも**縦スクロールができる**ようになります(事実H)。
  - 横方向のドラッグは従来どおり日付の変更です。横のパンは時間の窓で行えます(実装済み)。
- タップとドラッグの境界を、日単位ではなく**距離**にします(事実I)。
  - `endTaskDrag` の判定を `Math.abs(event.clientX - d.startX) < 6` にします。6px未満はタップとして扱い、日付を変えずに予定カードを開きます。
  - `moveTaskDrag` も、初回の移動が6px未満のうちは見た目を動かしません。
- タップ対象を44px以上にします。`•••` の当たり判定(S2)と、モバイルの予定名ラベルの高さです。

### S5. モバイルのガント表示で編集できるようにする

- 予定名ラベル(`06.js:134`)のタップで、選択と予定カードの両方が起きるようにします。
  - 原因は `10.js:20` の `!event.target.closest('input,button,select,textarea')` がラベル自身の `<button>` を掴むことです。
  - ラベルの要素を変えるのではなく、**`10.js:20` の除外条件を `input,select,textarea,[data-action]` に変えます**。行の中の `•••` は `data-action="details"` を持つため、従来どおり除外されます。
  - 事実B は左右どちらの表示でも起きうる形の不具合です。除外条件を直せば、呼び出し元をすべて塞げます。
- ラベルにも `•••` を出します(`06.js:134`)。一覧行と同じ `data-action="details"`。
- 行の高さを44px以上にします。

### S6. キーボードで右側へ届くようにする

いま、キーボードで触れるのは一覧の行だけです。ガント表示では何も選べません。
同時に、バーが全部 `<button>` なのでタブ停止が約280個あります(事実L)。この2つを一度に直します。

- バーとマイルストーンを `tabindex="-1"` にします。

## 要求の解釈について

「個別の右側でのアイコンをクリックしても、左側のメニュー同様、編集ができるようにしてほしい」には、二通りの読み方があります。

| 読み方 | 内容 | 本計画 |
|---|---|---|
| 狭い | バーに `•••` を1つ足し、押すと従来の詳細モーダルが開く | S2 だけで足りる。約30行 |
| **広い(採用)** | 右のバーと左の行が、同じ部品で同じだけ編集できる | S1〜S3。モーダルではなく予定カードを共有する |

広いほうを採用します。理由は3つです。

1. 狭い読み方では、モバイルのガント表示が救われません。詳細モーダルは画面を覆うため、期間を直す最中に前後の予定が見えなくなります。
2. 「左側のメニュー同様」を文字どおり満たすなら、左右が**同じ部品**を開くのが最短です。似せた別物を2つ持つと、片方だけ直る事故が起きます。
3. 予定カードは新しい保存経路を持ちません。`editorFormHTML` の項目と `contentCommit` をそのまま使います。狭い読み方との差は、枠の置き方だけです。

狭い読み方で十分であれば、S1 の「その場で直す」を省き、カードを読み取り専用にして「すべての項目」だけを置く形に縮められます。第1段の停止点で判断できます。
